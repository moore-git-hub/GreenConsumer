## 2. 方法证据库的初步结论

### 2.1 ODD 与 TRACE：模型说明和实验说明必须分开

Grimm 等（2020）的新版 ODD 协议将 ABM 描述划分为七个要素：

1. Purpose and patterns；
2. Entities, state variables and scales；
3. Process overview and scheduling；
4. Design concepts；
5. Initialization；
6. Input data；
7. Submodels。

该文尤其强调三点：

- 模型目的应与用于评价模型的目标模式同时提出；
- 每项设计不仅要说明“是什么”，还要解释“为什么这样设计”；
- ODD 描述的是作为虚拟实验室的模型本身，仿真实验、校准与模型分析应另设“Simulation Experiments”部分，并可通过 TRACE 文档记录模型开发、测试和应用过程。

对本研究的直接含义是：第三章可以采用“摘要式 ODD”重组模型机制；第四章说明实现与代码映射；第五章单独报告实验矩阵、随机性控制、参数扰动和重复运行，不能将三部分混写。

### 2.2 校准前必须先做敏感性和可识别性筛查

Platt（2020）比较多种经济 ABM 校准方法后指出，依赖人工调参或仅复现少量风格化事实，难以区分大量结构不同但输出相似的模型。其计算实验显示，似然型贝叶斯方法总体优于多种模拟最小距离方法，但当模型规模和待估参数维度升高时，性能明显下降。该研究在复杂模型中先使用 Morris 方法筛查参数敏感性，再仅校准具有足够输出影响的参数。

Grazzini、Richiardi 与 Tsionas（2017）进一步指出：ABM 缺乏解析似然，必须通过重复仿真估计；计算成本、汇总统计量选择和参数不可识别性是主要限制。复杂模型中出现宽后验或多个参数组合产生近似输出，并不一定是估计技术失效，也可能意味着模型过度参数化、设定错误或数据无法识别参数。

对本研究的直接含义是：当前不应一次性“校准”全部 Persona、敏感度、恢复率、锚点提升率、网络和注意力参数。应先做参数筛查，区分：

- 固定结构参数；
- 需要敏感性分析的关键参数；
- 具有外部数据时才适合估计的参数；
- 当前不可识别、只能作为情景参数的参数。

### 2.3 GABM 验证必须同时覆盖微观行为和宏观涌现

Park 等（2023）的生成式智能体研究采用两阶段验证：

- 受控评价：通过自我认知、记忆、计划、反应和反思等问题，评价单个 Agent 行为的可信度，并使用组件消融与人类评价者比较；
- 端到端评价：检查信息扩散、关系形成和群体协调等宏观涌现，同时主动报告幻觉、地点规范错误、过度礼貌与过度合作等失败模式。

Adornetto 等（2025）进一步主张，GABM 应将传统 ABM 的经验验证、采样、可视化、因果分析等方法，与微观面效度、宏观面效度、对话可信度、算法忠实度及人机混合评价结合起来。验证强度应与模型用途相匹配：用于探索机制的模型可以允许较弱的经验验证，但用于现实决策时必须提高证据等级。

据此，本研究的验证框架至少应包含：

1. 程序验证：公式、调度、数据记录和路由是否按设计执行；
2. 微观验证：同一 Persona 是否稳定、不同 Persona 是否可区分、直接澄清接收者是否产生合理反应；
3. 宏观验证：信任损耗、恢复、UGC 传播和渠道差异是否形成理论可解释的群体模式；
4. 消融验证：移除 Persona、锚点、记忆、网络和 LLM 语义判断后，结果如何变化；
5. 稳健性验证：跨随机种子、网络拓扑、LLM 模型和参数范围是否保持结论方向。

## 3. 原始数据完整性审计

### 3.1 通过的检查

当前数据结构完整：

- 12 个配置标签；
- 每个配置 30 个 Tick，共 360 条轨迹记录；
- 每个配置 20 个 Agent × 30 Tick = 600 条 Agent 记录；
- 总计 7,200 条 Agent-Tick 记录；
- 四类消费者配额在所有组中保持为 Active 3、Convenient 7、Dormant 8、Non 2；
- 社交角色保持为 Frequent Poster 6、Regular User 14，未生成 Lurker。

指标复算结果总体一致：

- `delta_recovery`、AUC、稳态信任、恢复率、T50、T80、最低点、基线信任和澄清窗口指标均能从轨迹数据复算；
- 无澄清组的 `recovery_speed` 存在 0.0001 的差异，属于轨迹 CSV 四位小数化后再复算造成的舍入误差；
- Agent 记录聚合后的平均信任与 `trajectories.csv` 一致，仅存在约 0.0001 的舍入差异；
- 7,200 条记录全部满足：最终信任 = `trust_after_decay + affective_change` 经 `[0,10]` 边界处理后的结果；
- 数据中只有 Tick 5 被标记为全局事件，说明批量实验的单事件 patch 实际生效；
- 12 组在 Tick 1—5 完全一致，延迟澄清组与无澄清组在 Tick 1—9 完全一致，表明澄清前 Replay 路径对齐生效；
- 四个无澄清配置的完整 Agent 记录完全相同，与全程 Replay 的设计一致。

### 3.2 当前数据不能支持的结论

当前材料只有一次网络、一次 Agent 配额分配和一次 LLM 路径，因而不能将图中的误差棒解释为重复实验的标准误或置信区间，也不能进行有效的显著性检验。现阶段图表只能作为单次机制演示或探索性结果。

## 4. 关键问题清单

## P0：必须在正式实验前解决

### P0-1  当前并非真正的 2×2×3 完全析因设计

当 `timing=no-clarification` 时，内容和渠道没有实际注入，因此四个无澄清标签是同一运行路径的复制。当前有 12 个配置标签，但只有 9 个实质条件：

- 2 内容 × 2 渠道 × 2 澄清时机 = 8 个澄清条件；
- 1 个共享无澄清对照。

不能把四个完全相同的无澄清单元当成四个独立观测进入三因素 ANOVA。正式设计应表述为“2×2×2 澄清策略析因实验 + 1 个无澄清对照”，或者使用适合带公共对照的模型比较方法。

### P0-2  `has_clarification` 字段错误标记了全部 Agent

当前每次只向 3 个目标节点直接投放澄清，但 `agent_records.csv` 在澄清 Tick 将 20 个 Agent 全部标记为 `has_clarification=True`。因此，当前数据无法区分：

- 直接接收企业澄清；
- 只接收邻居 UGC；
- 当日没有接收新消息。

这会直接妨碍“澄清回火效应”的判断。必须新增：

- `is_clarification_target`；
- `clarification_received`；
- `clarification_content_type`；
- `message_sources_received`；
- `target_out_degree`、`target_in_degree`；
- `target_cluster_type`。

### P0-3  当前 Hub 优势部分由网络构造规则机械保证

基准网络先生成无向 BA 图，再将每条边统一定向为“高度数节点 → 低度数节点”。在 N=20、m=2、seed=42 下：

- 13 个节点出度为 0；
- Hub 投放节点为 Consumer_000、Consumer_004、Consumer_001，出度分别为 13、10、6；
- Hub 三节点的直接下游并集覆盖 18 个节点，加上目标节点后覆盖全体 20 个 Agent；
- Random 投放节点为 Consumer_000、Consumer_017、Consumer_002，其中仍包含最高出度 Hub，另外两个节点出度分别为 0 和 1；
- Random 三节点加上下游只覆盖 15 个 Agent。

因此，Hub 与 Random 的差异不仅是策略效果，也包含固定网络方向规则、单一随机网络和目标人群构成差异。当前结果可以说明“在该构造网络中高出度投放覆盖更广”，但不足以一般化为现实社交平台中的 Hub 策略优势。

正式实验需要：

- 多网络种子重复；
- 保存网络边表与节点指标；
- 比较随机定向、双向/互惠边、真正的有向优先连接网络；
- 使用 ER、WS 和社群网络做结构稳健性检验；
- 对 Hub 与 Random 的目标群体类型构成进行匹配或统计控制。

### P0-4  论文与代码对信任恢复机制的描述不一致

论文当前倾向于表述为“没有正向信息时信任不自动恢复”。但代码实际逻辑是：只要当天没有 `current_news`，`quiet_ticks` 就累加并执行从 `shock_anchor` 向 `baseline` 的指数回归；即使 Agent 当天接收社交帖子，也可能同时执行时间恢复和语义冲击。

必须在以下三种机制中明确选择一种：

1. 无条件时间适应：危机后随时间自然向基线回归；
2. 条件性修复：只有接收正向信息或有效澄清才回归；
3. 双通道修复：弱自然适应 + 澄清引致的额外锚点修复。

第三种最适合当前研究问题，但需要将两条通道分开建模和记录，不能用同一“遗忘曲线”同时解释自然恢复与策略修复。

### P0-5  Reflect Prompt 注入当前数值信任，存在循环依赖

当前 Reflect Prompt 明确向 LLM 提供 `Current Trust Score: x/10`，但研究原则又要求 LLM 根据 Persona、文本和记忆自然形成反应，而不是读取数值信任后反向匹配输出。数值信任进入 Reflect 后，可能产生：

当前信任 → LLM 情绪冲击 → 更新后信任 → 下一轮再次作为 Prompt 输入。

这会使信任轨迹部分由分数提示自我强化。应设置“有数值信任”和“无数值信任”的消融实验；基准版本更建议不向 Reflect 暴露精确信任分，只提供定性记忆和当前信息。

### P0-6  当前没有独立重复，不能做推断统计

固定 N=20、seed=42、单一 BA 网络、单一路径缓存只能用于调试和机制对比。正式实验至少需要多个独立重复层级：

- Agent/网络生成种子；
- Random 渠道抽样种子；
- LLM 生成重复或不同模型；
- 必要时固定网络下的 LLM 重复与固定 LLM 路径下的网络重复。

Recording/Replay 是方差控制工具，不是样本重复的替代品。

## P1：应在数据记录和指标冻结前解决

### P1-1  `delay-3` 标签与实际注入时点不一致

代码标签为 `delay-3`，但实际澄清 Tick 为 `scandal_tick + 5`，即 Tick 10。建议统一改为 `delay-5`；若保留旧标签，论文必须只写“Tick 10 延迟澄清”，不能写延迟 3 天。

### P1-2  shock anchor 日志记录的是更新前值

Plan 层在完成锚点更新前，将旧的 `shock_anchor` 写入 `plan_result`，Agent CSV 因而无法直接观察澄清后的新锚点。应同时记录：

- `anchor_before`；
- `anchor_lift`；
- `anchor_after`；
- `anchor_update_reason`。

### P1-3  AUC 名称与实现口径不一致

指标说明称其为“丑闻后 AUC”，但代码实际上从信任最低点的下一 Tick 开始计算，排除了丑闻至最低点的损耗阶段。应二选一：

- 改名为 `auc_recovery_phase`；
- 或真正从 Tick 5 计算 `auc_post_scandal`。

建议同时保留两个指标：危机后全程 AUC 与最低点后恢复 AUC。

### P1-4  Recovery Speed 与 ΔRecovery 高度重复

当前所有策略的最低点都在 Tick 6，仿真终点也固定为 Tick 30，因此：

`recovery_speed = delta_recovery / 24`

两者近乎完全线性相关，不能作为两个独立目标重复加权。`plot_pareto.py` 的注释已经意识到这一点并尝试用稳态信任替代速度，但现有部分图表仍使用 Δ/AUC/Speed，指标体系尚未统一。

### P1-5  T80 当前没有区分度

所有策略的 T80 都等于 1，因为当前阈值被定义为 `baseline × 0.8`，而信任最低点仍高于该阈值。建议改为“恢复损失缺口的 80%”：

`target80 = trust_min + 0.8 × (baseline - trust_min)`。

### P1-6  `clarification_effect` 不能直接解释为因果澄清效果

该指标是群体平均信任在澄清前 3 Tick 与澄清后 3 Tick 的差值。它同时受到自然恢复、UGC 传播、直接投放比例和时间趋势影响。数据显示 Rational-Hub-Immediate 的群体窗口指标为负，但从 Agent 文本可见，其三个直接 Hub 目标中至少两个对证据内容表现为正向或谨慎正向反应。由此不能把群体窗口下降直接称为“澄清回火”。

更严谨的估计应包括：

- 直接目标 Agent 相对于同一 Agent 无澄清轨迹的差异；
- 非目标 Agent 的间接传播效应；
- 全体 Agent 的总处理效应；
- 澄清信息本身的 LLM 原始情绪响应分布。

### P1-7  内容操纵不是纯粹的“证据 vs 共情”

情感共情文本不仅包含道歉和共情，也包含消费者董事席位、约束性审查权和公开审计等强纠正行动；理性证据文本则包含数据、审计主体和文件披露。两种文本同时在情绪、证据、责任承担、治理承诺和具体性上变化。

正式实验前应进行操纵检验，至少评价：

- empathy；
- evidence strength；
- responsibility acceptance；
- corrective action；
- specificity；
- credibility；
- length/readability。

此外，Agent 实际看到的文本含有“Hypothetical experimental stimulus”提示，这会破坏情境沉浸。该免责声明应保留在研究文档和日志元数据中，但不宜作为企业声明正文输入 Agent。

### P1-8  缺少关键复现数据

当前输出包未包含：

- 网络边表；
- 目标节点列表；
- 节点中心性；
- 每 Tick 输入消息与来源；
- LLM 原始响应；
- 未缩放的 `trust_change_affective`；
- Prompt 与模型配置快照；
- Replay cache miss；
- Git commit、模型名、temperature、top-p 和运行环境。

这些数据缺失时，无法完整复现渠道机制、语义冲击和 Agent 级处理效应。

## P2：建议同步修复

1. Persona 体系定义了 Lurker，但其概率为 0；论文若写三类社交角色，应与实际生成保持一致。
2. 全部数据中 Active Greens 的正向 `affective_change` 最大值为 0，需检查是否来自 Persona 强约束、目标节点未覆盖 Active 人群或澄清文本不足，而不能直接解释为稳定心理事实。
3. `plot_pareto.py` 已将第三目标改为稳态信任，但策略排名 CSV 仍引用未定义变量 `speeds`，存在代码错误。
4. RecordingRouter 使用 Python 进程级 `hash()` 且只哈希 Prompt 前 200 字符；虽然同一进程内可工作，但不适合缓存持久化与跨运行复现，建议改用 SHA-256 全 Prompt 哈希。

## 5. 当前结果可以和不可以如何表述

### 可以表述

- 当前系统能够在固定 Agent、固定网络和固定澄清前 LLM 路径下生成可区分的策略轨迹；
- 单事件控制和澄清前 Replay 路径对齐在本次数据中按设计运行；
- Rational-Hub-Delay 配置在当前单次运行的多项描述性指标中表现较高；
- 企业澄清可能与持续负面 UGC 同时作用，导致直接目标反应与群体平均轨迹方向不完全一致；
- 购买行为与信任轨迹并非机械同步。

### 目前不能表述

- 某一策略具有统计显著优势；
- Hub 投放在一般社交网络中稳定优于随机投放；
- 即时澄清必然引发回火；
- 该参数组合已经被经验校准；
- 当前 12 个配置构成具有独立误差项的完整三因素析因实验；
- 当前结果能够代表真实消费者总体。

## 6. 下一步执行顺序

### 第一步：先做“不改变行为机制”的审计型代码补丁

优先增加：

1. `run_metadata.json`：commit、模型配置、随机种子、Prompt 版本和运行时间；
2. `network_edges.csv` 与 `node_metrics.csv`；
3. `target_nodes.csv`：渠道、目标节点、消费者类型、出入度；
4. Agent 记录新增 raw/scaled affective、clarification_received、message_sources、anchor_before/after；
5. 修复 `delay-3` 命名、`plot_pareto.py` 未定义变量和稳定哈希；
6. 将 12 标签改为 8 个澄清条件 + 1 个公共控制，或明确输出 9 个实质条件。

这一步不改变 Agent 心理机制，只提高可验证性和可复现性。

### 第二步：冻结指标口径

建议核心结果指标调整为：

- `trust_gain_vs_control`：最终信任相对公共对照；
- `auc_post_scandal`：Tick 5 至 Tick 30 的全危机期 AUC；
- `auc_recovery_phase`：最低点之后的恢复期 AUC；
- `max_trust_loss`：基线减最低点；
- `gap_recovery_ratio`：恢复的损失缺口比例；
- 购买/转化指标单独报告，不与信任指标混合为等权总分。

综合评分和 Pareto 分析只能作为辅助，不应替代逐指标统计分析；需要做权重敏感性检验。

### 第三步：决定信任恢复理论版本

在文献包“信任恢复、锚点和路径依赖”完成审读后，正式选择自然适应、条件修复或双通道恢复，并同步修改第三章公式与 Plan 层代码。

### 第四步：开展小规模验证实验

在正式 12/9 组策略实验前，先做四类验证：

1. Persona 可区分性；

3. 直接目标反应与公共对照比较；
4. 网络和随机种子的小规模重复。

验证通过后再扩大至正式重复实验和第五、六章写作。

## 7. 本轮结论

当前系统的程序运行和 CSV 聚合总体一致，单事件控制与路径对齐也已实际生效，说明模型已经具备继续开发的工程基础。但现有结果仍属于单次、固定网络下的探索性仿真。最需要优先解决的不是继续调整参数以增强区分度，而是完善处理标记、网络与目标节点日志、指标定义和重复实验结构，并统一论文与代码中的信任恢复机制。

在完成这些修复前，不建议将现有主效应、综合排名和澄清诊断图直接作为硕士论文的正式推断性结论。
